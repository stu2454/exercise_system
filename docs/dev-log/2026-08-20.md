### Client Demo onboarding and calibration

- Added Welcome, Prepare Your Space, Camera Setup, Positioning, three tutorial
  movements and Ready screens inside the existing Client Demo entry point.
- Deferred camera permission until the explicit **ENABLE CAMERA** action.
- Retained one camera stream through setup, tutorial and programme; the pose
  engine has one onboarding loop and is cleanly rebound at the programme UI
  boundary.
- Reused debounced participant framing guidance for tolerant positioning.
- Added simple canonical-pose tutorial detectors for a stable centred pose, both
  arms raised and lowered, and a sideways body-centre shift and return.

- Kept the session boundary explicit: tutorial observations do not create a

- Reused the existing canonical right-arm ready detector for hands-free
  continuation after each successful positioning/tutorial check. A 650 ms hold
  advances the screen; release-to-rearm prevents one held arm from skipping
  subsequent instructions. Manual fallback controls remain available.

## 4. Decisions made

| Decision | Rationale |
|---|---|
| Separate Vite root | Excludes the developer React application from the demo dependency graph instead of hiding it with CSS. |
| Derive, do not duplicate, the programme | Preserves one authoritative exercise/programme model and shared engine. |
| Override sets to one only | Produces the requested linear demo while retaining duration, rest and multi-round support elsewhere. |
| No routes | A single root page avoids GitHub Pages SPA fallback problems. |
| Resolve playback assets through `BASE_URL` | Supports localhost, domain-root and repository-subpath deployments. |
| Retain CDN pose assets | Keeps this stage small and static; offline/self-hosted MediaPipe is a later option. |
| Keep onboarding outside the runner | Setup is a usability aid, not an exercise, assessment or session metric. |
| Use canonical landmarks only | Tutorial heuristics stay independent of MediaPipe numbering and do not alter exercise recognition. |
| Never hard-gate calibration | Variable cameras and landmark visibility must not trap an external user. |
| Reuse the ready gesture | Participants can remain in camera position and the project keeps one tested anatomical right-arm interaction. |

## 5. Bugs identified and fixed

### Root-relative media under GitHub Pages

**Cause:** Canonical video and prompt paths begin at `/videos/` and `/audio/`,
which points at the domain root on a project Pages site.
**Fix:** Resolve the path against Vite's build base at the browser playback
boundary while retaining canonical library paths and validation.

## 3. Work completed this session

### Build 6 — Exercise Library, programmes and participant runner

#### Objective

Separate reusable exercises from programme prescriptions and provide a complete
local programme configuration and participant execution flow without adding a
backend or exercise-specific recognition.

#### Implemented

- Added typed exercise metadata, immutable library defaults and independent
  programme prescriptions while retaining duration, repetitions,
  repetitions-each-side, hold and free domain dose types.
- Configured the current nine reference exercises at 60 seconds, three circuit
  sets and 20-second transitions as non-clinically-validated development data.
- Corrected sequencing so one set is one complete ordered circuit through all
  programme exercises; mixed circuit set counts are rejected.
- Added duration completion, generic typed `repetition-completed` events,
  target-capped repetition handling and a developer `+1 Rep` control.
- Added pause/resume, restart, skip exercise, skip rest, zero-rest transitions,
  ready gesture, progress and completion behavior to the shared runner.
- Added versioned local programme persistence and a Programme Editor supporting
  create/select/rename/delete, exercise search/add/remove/reorder, dose targets,
  circuit sets, rest and demonstration preferences.
- Added semantic participant prompts with natural-audio preference, browser TTS
  fallback, manual voice selection and configurable volume/rate/pitch.
- Added structured `ProgrammeSessionResult` data with prescription snapshots,
  per-set duration/repetition outcomes, completion flags and compact intervals.
- Added a participant completion summary and robust restart/finalisation flow.
- Removed superseded `restAfterSeconds` and stale exercise-major documentation.

#### Key behaviour

```text
Set 1: Exercise 1 → … → Exercise 9
Set 2: Exercise 1 → … → Exercise 9
Set 3: Exercise 1 → … → Exercise 9
```

Participant and developer modes share one runner state machine. Repetition events
are ignored when paused, addressed to another exercise, applied to a duration
exercise, or received after the target. Skipped and aborted sets are not reported
as complete, including around zero-rest transitions.

#### Data/model changes

- Consolidated `Exercise.defaultPrescription` and programme-specific
  `ExercisePrescription` copies.
- Added generic runner event contracts with no MediaPipe dependency.
- Added versioned programme collection schema 1 under
  `exercise-engagement.programmes.v1`.
- Expanded `ProgrammeSessionResult` to retain programme, prescription, set,
  target, achieved-dose and completion information.

#### Materially affected components/files

Exercise types/library/validation, programme runner and events, programme
storage/editor, participant mode, audio prompt service, reference playback,
session tracker, tests and `docs/11-build-6-exercise-library.md`.

## 4. Decisions made

| Decision | Rationale |
|---|---|
| One set is one complete programme circuit | Matches the confirmed participant programme requirement and avoids exercise-major sequencing. |
| Circuit set count is shared | Mixed per-exercise counts are ambiguous under circuit sequencing. |
| Generic repetition event boundary | Validates programme behavior without prematurely adding pose-specific recognizers. |
| Keep application services above tabs | Navigation must not own or reset camera, pose, runner or programme state. |
| Keep inactive tab panels mounted | Preserves live Developer video/canvas DOM identity and the pose engine. |
| Separate launch from start | Entering participant presentation should not create an empty session or recording. |
| Persist structured results, not diagnostic streams | Keeps localStorage small and preserves the explicit privacy-oriented export model. |
| Snapshot programme names | Historical labels must survive later programme renames. |
| Conservative completion counting | Tracking failure, skips and partial work must not be falsely reported as completion. |
| Use status plus daily logs | A concise current-state file supports handover, while chronological logs retain decisions and debugging context. |

## 5. Bugs identified and fixed

### Bug — Browser voice reverted during a programme

**Observed behaviour:**
A manually selected US voice initially worked, then later prompts used the
automatic Australian voice.

**Cause:**
Browser voice discovery can temporarily return a partial list. The selected URI
was then absent and automatic locale ranking selected en-AU; the speech adapter
also performed a second fresh lookup.

**Fix:**
Retain cumulatively discovered voice options and cache the actual selected
`SpeechSynthesisVoice` for the session.

**Regression protection:**
Voice tests cover manual selection surviving partial voice-list refreshes.

### Bug — Continue Session lost the camera display

**Observed behaviour:**
After the end-session confirmation, Continue Session could show no camera even
though the stream had not been stopped.

**Cause:**
The confirmation screen unmounted the participant video element. The active
stream was not attached to the replacement element after continuing.

**Fix:**
Explicitly reattach the existing stream when the participant surface remounts.

**Regression protection:**
The fix reuses the existing `reattachVideo` service and does not call camera
start, permission or pose reset paths.

### Bug — Participant Mode had no pre-start camera surface

**Observed behaviour:**
Launching Participant Mode from Overview showed no live camera even when the
Developer camera was active.

**Cause:**
The new idle participant screen mounted neither the shared video nor pose canvas,
leaving the active stream and pose engine without a participant surface.

**Fix:**
Mount exemplar, live camera, pose canvas, programme summary and Start Programme
before the programme starts. Retain the same camera/canvas nodes through idle,
Ready and Exercising.

**Regression protection:**
The participant layout no longer conditionally removes these surfaces during
normal programme start transitions.

### Bug — Exemplar video was static before the ready gesture

**Observed behaviour:**
The first or next exercise exemplar could remain frozen until the participant
raised their right arm.

**Cause:**
Playback relied on an early imperative play request, and between-exercise rest
explicitly disabled next-exercise playback.

**Fix:**
Add native muted autoplay plus a media-readiness retry, and keep the next
exercise preview active during rest according to its before-exercise preference.

**Regression protection:**
Demonstration tests cover Ready playback, rest preview, pause and programme
preferences independently of gesture/pose state.
